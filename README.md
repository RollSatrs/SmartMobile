# SmartMobile

Мобильный клиент Smart City для жителей области Абай. Проект работает на React Native и Expo.

## Запуск

```bash
npm install
npm start
```

Для проверки типов:

```bash
npm run typecheck
```

## Авторизация

До готовности `RollSatrs/SmartBackend#2` приложение по умолчанию использует mock-адаптер, соответствующий черновому API-контракту:

- `POST /auth/register` — `{ name, email, password, role }`;
- `POST /auth/login` — `{ email, password }`;
- ответ — `{ user, accessToken }`.

В mock-режиме адрес, начинающийся с `gov`, открывает кабинет госоргана; любой другой адрес открывает кабинет жителя. Пароль должен содержать минимум шесть символов.

Для подключения реального API задайте переменные окружения:

```env
EXPO_PUBLIC_USE_MOCK_AUTH=false
EXPO_PUBLIC_API_URL=http://192.168.1.10:3000
```

На iOS и Android токен и данные пользователя сохраняются через `expo-secure-store`; в web-preview используется `localStorage`. Защищённые экраны не входят в дерево навигации, пока сессия не восстановлена.

## UI

Для issue #1 выбрана библиотека **React Native Paper**: она совместима с Expo, предоставляет доступные Material-компоненты и не требует собственной нативной сборки для базовых элементов форм.

## Форма идеи

До появления `/ideas` в Swagger форма работает через mock-адаптер по контракту `RollSatrs/SmartBackend#3`:

- обязательные название, описание, фотография и координаты;
- район определяется после выбора точки;
- создание возвращает статус `received`;
- mock-классификация через короткую задержку заполняет категорию и пояснение.

Для карты выбрана библиотека **react-native-maps**. В мобильном приложении точку можно поставить нажатием, перетащить или определить через геолокацию устройства. Для web-preview используется облегчённая заглушка карты. Фото выбирается через **expo-image-picker** — из камеры или галереи.

Когда Backend #3 будет опубликован в Swagger, методы в `src/ideas/ideaService.ts` нужно сверить с `/docs`: сейчас реальный адаптер подготовлен для `POST /ideas` и `GET /ideas/:id`, а отдельный эндпоинт reverse geocoding ещё не опубликован.

## Кабинет жителя

Пока `GET /ideas` и история статусов не опубликованы в Swagger, кабинет использует демонстрационные данные и сохраняет их через **AsyncStorage**. Новые идеи из формы попадают в начало списка. Доступны:

- сводка по общему количеству, активным и завершённым идеям;
- фильтры по состоянию;
- индикатор непрочитанных изменений;
- детальная карточка с категорией, районом, координатами и полной временной шкалой;
- комментарии государственного органа в истории статусов;
- pull-to-refresh и обработка ошибок.

Открытие детальной карточки помечает обновление как прочитанное. Реальный адаптер ожидает контракт `GET /ideas?page=1` → `{ items, total }` и `GET /ideas/:id` → идея со `statusHistory`; его необходимо сверить с `/docs` после реализации Backend #3/#4.
